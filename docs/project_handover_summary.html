Executive Mission: Kenyan Savings and Credit Cooperative Organizations (SACCOs) serve millions of members ranging from tech-savvy young professionals to rural, less digitally literate elders. Traditional customer service (long branch queues, congested phone hotlines, and complex online portals) creates severe friction. This platform provides an intelligent, conversational WhatsApp-first member companion paired with a centralized multi-tenant staff operations dashboard, delivering instant, grounded SACCO assistance with zero hallucinations and sub-second response times.

1. Core Value Proposition: "Not Just Another Chatbot"

The system rejects the traditional open-ended LLM chatbot model that frequently invents interest rates, dividends, or loan limits. Instead, it enforces strict deterministic separation between general knowledge RAG, mathematical planning, and sensitive personal financial data:

Cardinal Architectural Principle

Sensitive & member-specific requests must NEVER pass through general document RAG. When a member asks "What is my loan balance?" or "How much can I borrow?", semantic vector search is strictly forbidden. The request routes to an authoritative Member Data Service fetching deterministic ledger records via SHA-256 phone hashing.

Zero-Hallucination Math Engine

LLMs are strictly forbidden from performing financial arithmetic. All financial goal projections, required monthly savings, interest amortizations, and what-if scenarios are calculated deterministically by GoalCalculator in <1ms before presentation.

6. Developer & Gemini Handover Protocol (Operational Playbook)

Immediate Instructions for Gemini / Incoming Engineer:

Environment Activation: Always activate conda env whatsapp_sacco (conda activate whatsapp_sacco).
Start Vector Store: docker compose -f docker_compose.yml up -d qdrant (verifies collection sacco_knowledge).
Start Application Server: uvicorn app.main:app --reload --port 8000 (pre-warms embeddings and conversation services on startup).
Run Database Migrations: python scripts/migrate.py (executes migrations 001 to 006 explicitly; app never auto-mutates schemas).
Run Test Suite: python -m pytest -v (validates all 372 collected unit and integration tests).
Run Offline RAG Evaluation: python scripts/evaluate_rag.py (tests retrieval and answerability without consuming Groq tokens).
Expose to Twilio: Launch cloudflared-windows-amd64.exe tunnel --url http://localhost:8000 and paste URL into Twilio Sandbox webhook (/webhooks/whatsapp).
Key Codebase Structure

• app/api/routes/: FastAPI routers (whatsapp, rag, members, goals, education, proactive, admin, sacco_sandbox)
• app/services/conversations/: Context, state, triage pre-filter, dispatcher, workflow handlers
• app/services/goals/: Deterministic math calculator and natural language goal extractor
• app/services/rag/: Grounded answer service, knowledge gap intelligence, Qdrant repository
• app/static/dashboard/: Modern glassmorphic Admin Operations SPA

Key Architectural Constraints

1. Do Not Re-introduce LLM Math: Keep GoalCalculator pure Python.
2. Never Pass Member Balances to RAG: Enforce the member-data fast-path separation.
3. Observe Groq 8k TPM Limit: Avoid unconstrained parallel LLM chains.
4. Preserve Privacy: Never log or persist plain-text phone numbers; use SHA-256 hashes.
